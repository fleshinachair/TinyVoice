# TinyVoice

Schwung `audio_fx` module for Ableton Move: a vocal processor with four engines (Vocoder, Voice FX, Resynth, Mangler), 13 modes in the Mode list, a home page of eight knobs (VOICE) and PITCH, MORE and LOOPER pages. Freeze is a 16 s looper on the input; Demo is a built-in sung phrase. No delay or reverb (the chain has its own).

Module id `tinyvoice`, library `tinyvoice.so`, archive `build/TinyVoice.tar.gz`, include guards `TINYVOICE_*`, widget kinds `custom:tinyvoice_*`, C prefix `vt_` / `VT_`.

## Commands
- `bash scripts/test.sh` - native tests (`tests/test_main.c`). Must stay green. `SANITIZE=1` adds UBSan.
- `bash scripts/build.sh` - cross-compile and package `build/TinyVoice.tar.gz`. `bash scripts/install.sh [--build]` - sideload to the Move.
- `bash scripts/smoke_on_device.sh` - runs the installed `.so` on the Move.
- Compiler is zig, target `aarch64-linux-gnu.2.35` (glibc, not musl), `-std=c11 -Wall -Wextra -Werror -pedantic`. Never `-ffast-math` (it can pull in libmvec, which the device lacks).

## Rules that matter
- Only `src/dsp/plugin.c` touches the Schwung ABI. Everything else in `src/dsp/` has no Schwung includes.
- Realtime: every entry point runs on the audio callback. After `dsp_init` there is no allocation, locking, I/O or large stack use.
- The library must be named `<id>.so` (`tinyvoice.so`, never `dsp.so`). `move_audio_fx_on_midi` must stay exported or pads get no MIDI. `build.sh` and `smoke_on_device.sh` check both.
- `module.json` and `src/dsp/module_meta.h` are generated by `scripts/gen_module_json.py`. `k_params` in `dsp.c`, `PARAMS` in the generator and `module.json` must agree; the test enforces it, so edit them together.
- Mode order lives in `vt_mode` (`dsp.h`), `k_mode_opts` (`dsp.c`), `MODES` in the generator and `MODES` in `canvas.js`.
- Everything is tuned on synthetic signals only. Judge by ear on a real voice; do not claim a mode sounds right from measurements alone.
- The calibration lab is outside this repo (`C:/Github/TinyVoice-lab`). Never commit Humanoid presets or `.baby` files, or presets imported from PitchMonster (`*.preset`, `build/pitchmonster_presets/`).
